# Security Policy

The Nimbopacks team takes security vulnerabilities seriously. We
appreciate responsible disclosure and will work with you to investigate
and resolve any issues.

## Supported Versions

Nimbopacks is pre-1.0 software. Security fixes are released against the
latest minor version on the `main` branch. Once a `1.0` release is cut,
this section will be expanded to cover an explicit support window.

| Version  | Supported          |
| -------- | ------------------ |
| `0.x.y`  | :white_check_mark: latest minor only |
| `< 0.x`  | :x:                |

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub
issues, discussions, or pull requests.**

### Preferred: GitHub Private Vulnerability Reporting

Report vulnerabilities through GitHub's private vulnerability reporting
feature:

1. Navigate to <https://github.com/Nimbostack/nimbopacks/security/advisories/new>
2. Fill in the form. GitHub notifies the maintainers privately.

This is the fastest path to triage and produces a GitHub Security
Advisory (and, where appropriate, a CVE) once the issue is resolved.

### Alternative: Email

If you cannot use GitHub Security Advisories, email
[security@nimbopacks.io](mailto:security@nimbopacks.io). Please encrypt
sensitive details where possible.

### What to include

To help us triage quickly, please provide:

- A description of the vulnerability and its impact
- Steps to reproduce, or a proof-of-concept
- The version of Nimbopacks affected (commit hash, release tag, or
  container image digest)
- Your operating system and architecture
- Any suggested remediation or mitigation

## Disclosure Process

We follow a coordinated disclosure model. The expected timeline:

| Step                                              | Target              |
| ------------------------------------------------- | ------------------- |
| Initial acknowledgement of report                 | within 3 business days |
| Triage, severity assessment, and reproduction     | within 7 business days |
| Fix developed, reviewed, and tested               | within 30 days for high/critical |
| Patch released and security advisory published    | coordinated with reporter |
| Public disclosure                                 | within 90 days of report, or sooner if a fix is shipped |

If a vulnerability is being actively exploited, we may accelerate the
timeline and ship a fix before the standard window closes.

Once a fix is released, a security advisory is published at
<https://github.com/Nimbostack/nimbopacks/security/advisories>.

## Scope

This policy covers the Nimbopacks codebase in this repository, its
released container images on `ghcr.io/nimbostack/nimbopacks`, and any
first-party tooling distributed by the project.

**Out of scope:**

- Vulnerabilities in upstream dependencies — please report those to the
  upstream project directly:
  - [melange](https://github.com/chainguard-dev/melange/security)
  - [apko](https://github.com/chainguard-dev/apko/security)
  - [grype](https://github.com/anchore/grype/security)
  - [Wolfi packages](https://github.com/wolfi-dev/os/security)

  If a Nimbopacks default or integration amplifies an upstream issue,
  that *is* in scope.
- Vulnerabilities in user-supplied `nimpack.yaml` configurations, build
  commands, or third-party packages a user adds to their image.
- Social engineering, physical attacks, or denial-of-service against
  the project's infrastructure.

## Supply Chain Security

Nimbopacks releases ship with:

- **SBOMs.** Every published OCI image includes an SPDX SBOM generated
  by apko at build time. Release binaries (via GoReleaser) include
  SBOMs generated by syft.
- **Keyless signatures.** Each release image is signed with
  [cosign](https://github.com/sigstore/cosign) using the Sigstore
  public-good infrastructure. The signature identity is bound to the
  GitHub Actions workflow that built the image, so verification proves
  both *who* built it and *how*.

Verify a release image before deploying:

```bash
cosign verify ghcr.io/nimbostack/nimbopacks:latest \
  --certificate-identity-regexp="https://github.com/Nimbostack/nimbopacks/.github/workflows/release.yml" \
  --certificate-oidc-issuer="https://token.actions.githubusercontent.com"
```

For images you build *with* Nimbopacks, we recommend running
`nimbopacks update --check` in CI to gate on CVEs at or above your
chosen severity threshold.
